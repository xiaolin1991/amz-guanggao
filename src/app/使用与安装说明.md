## 一、 本次 v1.3.0 全量 Bug 修复汇总

### 1. 图一相关问题修复（1.1 ~ 1.4）
* **1.1 彻底修复“乱识别为广告组/状态词/数字、识别不到当前页面关键词”**：
  * **原因**：旧版代码在 `extractPureKeywordText` 中使用了 `querySelector('a, .kw-name, [title]')`，而在真实亚马逊广告后台的【定向策略（关键词）】页面中，关键词是纯文本（非 `<a>` 链接），且中文释义旁带有 `<span title="...">ⓘ</span>` 提示图标。旧代码误将 `ⓘ` 图标匹配并清空后返回空字符串 `""`，进而触发兜底循环，把第 4 列状态 `不完整`、第 5 列 `建议竞价 US$1.14(...)` 或纯数字 `29,157` 误判为关键词；同时 `querySelectorAll` 把外层 `[role="gridcell"]` 与内层 `.data-table-cell` 重复计入，导致所有列索引整体向后偏移 +3 列；且 SPA 切换页面时未清理旧缓存。
  * **修复方案**：
    1. 新增 `getTopLevelCells(row)` 与 `getTopLevelHeaderCells(root)`，彻底剔除嵌套包裹的子节点，杜绝列索引偏移；
    2. 重构 `extractKeywordInfo(cell)` 与 `isValidKeywordText(txt)`，采用 `TreeWalker` 提取真实关键词与中文释义，严禁误抓 `ⓘ` 的 `[title]`，并严密拦截 `不完整`、`进行中`、`超出预算`、货币符号与纯数字；
    3. 新增 SPA 路由、表头签名与搜索框过滤词联动检测（`checkAndResetStoreOnContextChange`），当从【广告活动】切入【广告组】再进入【定向策略/关键词】时自动清空旧层级缓存，且在关键词页面自动过滤掉非关键词行；
    4. 存储键升级为按 `关键词 + 匹配类型（广泛/短语/精准）` 独立存储，防止同词不同匹配方式互相覆盖。
* **1.2 修复“顶部导航处（快扫全表、监控中、亮色）文字竖向折行 UI 错乱”**：
  * **原因**：面板头部宽度不足且按钮未设置 `white-space: nowrap` 与 `flex-shrink: 0`，导致文字被挤压成竖排多行。
  * **修复方案**：面板拓宽至 `482px`，为 `.xl-header-actions` 及所有头部按钮强制设定 `flex-wrap: nowrap !important; white-space: nowrap !important; flex-shrink: 0 !important; height: 26px !important;`，五个操作按钮严格单行水平对齐。
* **1.3 修复“警告徽章遮挡广告活动预算/建议竞价，需固定在第一列名称处且小巧精致”**：
  * **原因**：旧版因列偏移将徽章插入到了第 5 列（预算列/建议竞价列），且未彻底过滤 `tfoot`/汇总行，徽章尺寸偏大。
  * **修复方案**：严格将 `.xl-inline-badge` 锁定在第 1 列（关键词/广告活动名称/广告组名称列）内部，并自动清理同行其他列的任何残留徽章；彻底排除 `总计` / `Total` 汇总行；徽章尺寸缩小至 `height: 15px; font-size: 9.5px; padding: 0 5px;`，小巧醒目且绝不遮挡数据。
* **1.4 修复“点击【🎯 定位】后关键词所属列没有醒目框框”**：
  * **原因**：旧版 `content.css` 在 `@keyframes` 内部使用了 `!important`（违反 W3C CSS Animations 规范，导致 Chrome 直接忽略整个动画中的所有 `outline` 和 `background-color` 属性）。
  * **修复方案**：移除 `@keyframes` 内非法的 `!important`，为目标关键词单元格 `.xl-kw-cell-focused` 直接赋予高对比度 `3px solid #dc2626` 醒目红色聚焦框、柔粉底色高亮与 `🎯 当前定位` 胶囊标签，同时整行呈现金色背景高亮。

### 2. 图二相关问题修复（2.1 ~ 2.3）
* **2.1 修复“未获取到关键词、77次展示量被识别为1.35次、真实竞价1.06被识别为1.0”**：
  * **原因**：列索引偏移 +3 导致插件把 `总成本/CPC (US$1.35)` 当成了展示量，把 `点击量 (1)` 当成了竞价；且亚马逊竞价列内的数值位于 `<input value="1.06">` 中，而旧版仅读取 `.textContent`（`<input>` 的 `textContent` 为空），导致回退为默认值 `1.0`。
  * **修复方案**：通过 `ARIA 列号 + 表头视觉 X 坐标对齐 + 顶层去重索引` 三重机制锁定真实列；新增 `extractBidFromCell(bidCell)` 优先读取单元格内 `<input>` 的 `value` / `placeholder`，准确读取 `1.06`；新增 `extractImpressionsFromCell(impCell)` 严格排除含 `$` 或 `%` 的列，准确读取 `77` 次展示量。
* **2.2 修复“点击【应用竞价】跑到点击量列新建方框，未能在后台真实竞价列修改成功”**：
  * **原因**：列偏移导致 `autoFillSuggestedBid` 定位到了点击量列，且未正确触发亚马逊 React 受控输入框的状态同步与保存确认。
  * **修复方案**：在 `autoFillSuggestedBid` 中增加表头二次安全校验（严禁触碰点击量、展示量、建议竞价、总成本列）；支持直接写入竞价列常驻 `<input>` 或派发完整鼠标指针序列唤醒行内编辑器，通过 `HTMLInputElement.prototype.value` 原生 setter + 重置 React `_valueTracker` + 派发 `input/change/Enter` 事件并自动点击确认按钮完成后台竞价修改；同时锁定原始竞价 `data-xl-orig-bid`，避免修改后二次重扫叠加计算。
* **2.3 修复“【降价止损】中的关键词报警缺少与【曝光激活】一致的原竞价 -> 建议竞价自定义输入框”**：
  * **原因**：旧版在 `renderPanelDiagList` 中对高花费 0 转化词仅渲染了文字提示与否定按钮，未提供自定义改价输入框。
  * **修复方案**：重构 `analyzer.js` 与 `renderPanelDiagList`，使【🛑 降价止损】下的所有卡片统一显示 `原竞价: US$X.XX ➔ 建议竞价: [$ 自定义输入框] [应用竞价]`，吃预算词同时保留 `[复制否定]` 快捷按钮。

### 3. 图三相关问题修复（3.1 ~ 3.3）
* **3.1 修复“表格顶部第一行警告悬浮窗向上弹出被表头顶住遮挡，无法看到建议”**：
  * **原因**：旧版 `.xl-inline-tooltip` 写死 `bottom: calc(100% + 6px)` 向上弹出，且受父级 `transform` 影响导致坐标偏移或被表头截断。
  * **修复方案**：新增 `updateInlineTooltipPosition(badge)` 智能方向判断，当徽章靠近表头下沿或视口上方时自动切换为 `.xl-tooltip-down`（`top: calc(100% + 6px)` 向下展开），并自动提升当前单元格与行的 `z-index` 层级，彻底解决被表头遮挡问题。
* **3.2 修复“明明展现量有 570 次却被误报为【曝光不足】”**：
  * **原因**：旧版列偏移将 `face roller`（展示量 570、点击量 1、花费 US$1.01）的点击量 `1` 或花费 `1.01` 误读为展示量（`<= 5`），从而产生误报。
  * **修复方案**：修复列对齐与展示量整数校验后，`570` 次与 `77` 次展示量均 100% 精准识别，绝不再误判为曝光不足。
* **3.3 修复“未下拉的虚拟滚动列表不抓取、展示量为 `—`（0曝光）的关键词未识别”**：
  * **原因**：① `analyzer.js` 原判断条件为 `impressions > 0 && impressions <= lowImpThreshold`，导致亚马逊后台显示为 `—`（即 `0` 次展示量）的大量未曝光关键词被全部漏掉；② `findTableScrollContainer` 仅向上查找父元素，未查找表格内部的虚拟滚动视口（如 `.ReactVirtualized__Grid` / `.ag-body-viewport`）；③ `MutationObserver` 未过滤插件自身 DOM 变动，导致每 450ms 无限重绘面板。
  * **修复方案**：
    1. 将低曝光判定升级为 `impressions >= 0 && impressions <= lowImpThreshold`，并将 `—` 准确解析为 `0` 次展示量，使所有 0 曝光词全部进入【💤 曝光激活】；
    2. 升级 `findTableScrollContainers()` 支持双向查找内部与外部虚拟滚动容器，`fastScanFullTable()` 按视口高度 70% 分步穿透滚动并实时汇入 `XiaolinRowStore` 全局缓存池；
    3. 修复 `MutationObserver` 过滤插件自身节点变动并加入渲染签名比对缓存，彻底消除面板无限闪烁重绘。

## 二、 极速安装指南（以 Chrome / Edge 为例）

1. 打开浏览器扩展管理页面：
   * **Chrome 浏览器**：地址栏输入 `chrome://extensions/` 并回车。
   * **Edge 浏览器**：地址栏输入 `edge://extensions/` 并回车。
2. 开启页面右上角的 **“开发者模式” (Developer mode)**。
3. 点击左上角 **“加载已解压的扩展程序” (Load unpacked)**，选择本目录下的 **`xiaolin-ad-assistant`** 文件夹即可立即使用（或直接拖拽 `.crx` / 解压 `.zip` 安装）。
4. 双击打开 `xiaolin-ad-assistant/test_mock_amazon.html` 可在本地离线沙盒中直接测试所有修复效果。
